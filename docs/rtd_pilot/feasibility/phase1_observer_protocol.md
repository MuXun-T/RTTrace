# Phase 1 independent observer protocol

DSLogic is the observer truth source for GPIO transitions; UART is an independent cross-check. Neither consumes parser, metric, diagnoser, Agent, CCM, Ledger, or lineage output. DSLogic raw files and UART logs remain outside the repository, are hashed, and are retained even when invalid.

Observer GPIO uses 2 MHz general-purpose push-pull drive, not the STM32F1 50 MHz output setting. This is an electrical signal-integrity control for the adjacent logic-analyzer leads; it changes neither pin-map version nor logical polarity, and every capture remains bound to its exact firmware hash.

Export a normalized DSLogic CSV with `timestamp_s` and the selected channel values, retain the vendor raw capture beside it, then create a nonempty observer summary JSON containing `epoch_begin_sequences`, `epoch_end_sequences`, `all_required_channels_nonflat`, `capture_complete`, and SHA-256 bindings to both raw and normalized observer files. Run `analyze_clock.py` over real calibration-edge timestamps and provide its nonempty clock-analysis JSON, including measured `drift_ppm`, `alignment_residual_max_s`, and hashes of CSV/UART/epoch inputs. The validator hashes every raw/normalized/artifact/summary/analysis file and independently parses UART epoch lines; it does not use parser output as truth.

If the CH340 USB-serial reopen interval demonstrably omits the earliest post-reset UART records, `prepare_dsview_observer.py --discard-leading-epochs N` may be used only with an explicit positive `N` that leaves at least one Observer edge. It retains the discarded count and timestamps in the summary and maps the first retained edge to the first actually present UART sequence. This is an alignment declaration, not reconstruction: no missing sequence, timestamp, or observer edge is created.

An independent Phase 1 session may use pre-arm halt/resume rather than a target reset: halt the MCU before DSView is armed, arm the Observer while CH0 is quiescent, then resume it to produce the next real Epoch. The halt must occur before the capture window and be recorded as `session_start_method=halted_resume`; no reset, halt, or fault is permitted once the formal capture begins. This session method is used when system-reset pin initialization itself produces a physical transient on the Observer wiring. It is not represented as a reset capture.

For capture-gated RTOS smoke builds, CH0 remains inactive after boot until the UID-pinned SWD gate tool writes the firmware-hash-bound `capture_armed` RAM symbol. Each release permits exactly one complete Epoch interval, then firmware clears `capture_armed` and returns CH0 inactive. The `RTD1 CAPTURE_ARMED source=swd_gate` UART record precedes that Epoch. A formal capture must arm DSView first and use a persistent SWD session to write the release; no target inspection, halt, reset, debugger disconnect, or serial reopen is allowed during the subsequent DSView window. `arm_capture_gate.sh --emit-persistent-command` performs only ELF/metadata preflight and prints the one `write32` command for that already-attached session; it never attaches or disconnects a debugger.

The Fire V2 CH340 path is not assumed electrically passive: opening `/dev/ttyUSB0` has repeatedly placed this board in STM32 System Boot ROM. Therefore a Task smoke cross-check uses a single persistent `capture_uart.py --ready-file` reader before Flash startup, never a reopen after startup. Once the ready file exists, start the Flash vector through the persistent SWD session, retain `session_start_method=swd_flash_vector_start`, and verify that the still-running UART file receives the RTD1 `BOOT` line before DSView is started. This is a manual Flash-vector start, not reset evidence. If the BOOT line is absent, preserve the UART file and stop: do not arm DSView or release an Epoch. After DSView reports waiting for CH0, write the emitted single-use gate command in the same SWD session. No target operation, debugger disconnect, or serial reopen is permitted until the 5 s DSView window ends.

The firmware uses TIM2 with HSI-derived configured input `8,000,000 Hz`, prescaler `0`, auto-reload `3999`, update `2,000 Hz`, and a PC3 GPIO toggle in each TIM2 update ISR: nominal calibration square wave `1,000 Hz`. It is timer-scheduled rather than a timer output-compare waveform, so ISR latency/jitter must be measured and retained. PC2 is raised at `EPOCH_BEGIN` and lowered at `EPOCH_END`; UART emits the same monotonically increasing sequence and contemporaneous tick values through USART1 PA9. PC4/PC5 mark actual task CPU-work windows, PC6/PC7 mutex hold/wait, PB5 the separately controllable TIM3 IRQ span, and PB0 the minimal recorder-pressure interval. PB5/PB0 are low-active LEDs but the Observer uses high-active physical logic, so active means the relevant LED is off.

Freeze DSView before H2 using one of two metadata-bound profiles. `calibration_20mhz` enables CH0--CH7, disables external-clock sampling, uses a 1.65 V digital threshold (or the nearest documented DSView setting), samples at 20 MHz for 5 seconds, triggers on CH0 rising, and retains the raw file. `irq_precision_100mhz` enables the same channels and threshold, disables external-clock sampling, samples at 100 MHz for 500 ms with 20% pre-trigger, triggers on CH6 rising, and requires every retained PB5 pulse to span at least two samples. A missing trigger, fewer than two samples, an enabled external-clock mode, or an unavailable rate is invalid evidence, not an inferred ISR duration. The recorded DSView device, threshold, rate, duration, trigger, enabled channels, clock source, and profile name must match metadata.

Pin identities are frozen as `phase1-pinmap-v2` from the supplied silkscreen photo and are recorded in `phase1_pin_map.md`. Before power-on, the operator must still confirm the UART jumper selects CH340 to USART1 PA9/PA10 and that no local add-on consumes the named pins.
