# RTD-PILOT P8 Work Plan (planning only)

Status: **PLAN REVIEW REQUIRED**. This append-only plan is the sole Phase-1
output. It authorizes no implementation, evidence generation, or hardware
access.

## 1. Objective, scope, and completion gate

P8 will extend the sealed P7 evidence chain with the smallest independently
auditable follow-up work. P5 Observer/OAR/CVR and the frozen P7 derived outputs
remain read-only inputs; no parser, diagnoser, Agent, Advisor, screenshot,
synthetic, replay, or report-only artifact may become Observer truth. Scope is
limited to (a) offline schema/lineage/manifest audit and any explicitly
approved derived analysis, (b) append-only P8 records and tests, and (c) a
hardware track that is fail-closed unless separately authorized. No new
hardware capture, flash, reset, UART, serial, SWD, or board command is planned.

P8 is complete only when every planned non-hardware check passes; each new
record has unique `record_id`, schema/version, source_refs with reachable
relative paths and SHA-256, identity, lineage, episode and parent_record_id;
duplicate/cross-case/stale-binding/split/superseded/correction/failed/retry/
invalid/non-manifested states are retained; a unique manifest covers every
new file; protected P5/P6/P7 inputs and anchors are byte-identical; full
regression and integrity audits pass; and hardware status is explicitly
COMPLETE or BLOCKED (never inferred).

## 3. Allowed P8 changes and artifacts

After primary-agent approval, add only a new unique
`docs/rtd_pilot/p8_execution_<UTC>/` tree (records, manifest, regression and
closeout) plus narrowly scoped P8 audit/test tooling explicitly approved in
this plan. Existing P5/P6/P7 raw evidence, Observer/OAR/CVR, threshold,
profile, registry, P4/H8 anchors, freeze/audit/regression/manifest/correction
records are immutable. Current unrelated worktree edits are preserved.

## 4. Work split and evidence sources

**Offline/non-hardware (priority):** verify P7 commit/tree and listed hashes;
run existing P7/P6/P5 read-only audits; inventory schemas and helpers; design
and implement only approved append-only P8 validation/derived records; test
JSON/YAML/schema, source reachability, SHA-256, identity, lineage/episode,
parent/supersedes/correction chains, duplicate/cross-case/stale/split and
no-overwrite; regenerate a P8 manifest and regression report. Every source
reference points to the exact P7 frozen file (or an approved immutable P5/P6
record) with role and hash. Derived outputs explicitly carry
`observer_truth: false`, `truth_boundary`, P7 `parent_record_id`, and cannot
upgrade synthetic/replay/advisory evidence.

**Hardware:** not executable under current authorization. If later authorized,
record authorization ID, device/firmware identity, bounded capture scope and
stop conditions first; use existing gates only. On unavailable/unauthorized
hardware, append a BLOCKED/FAILED attempt record (never delete or overwrite)
and continue all offline work.

## 5. Record and retention contract

Use a versioned `rtd-p8-*-v1` schema. Required fields: `record_id`,
`record_type`, `phase`, `created_at`, `append_only`, `hardware_action`,
`source_refs[]` (relative path, SHA-256, role), `identity`, `lineage`,
`episode`, `parent_record_id`; include `correction_of`/`supersedes` when
applicable. Unique output directory creation must use exclusive create/no
overwrite. Preserve duplicate, cross-case, stale-binding, split, failed,
retry, invalid, correction, superseded and non-manifested history as records.

## 6. Dependencies, risks, and stop conditions

No new package, network, credential, manual labeling, or external resource is
needed for offline scope. Stop immediately on P7/P6/P5 hash/tree/commit drift,
protected-path modification, stale or cross-case binding, missing source/hash,
truth-path contamination, manifest omission, or any attempted hardware access.
Rollback means retain files and append a correction/superseded/blocked record;
never reset, delete, rename, or rewrite history. Potential worktree edits
listed by `git status` are unrelated and must not be staged or changed.

## 7. Verification and handoff

Run focused P8 tests, existing P7/P6/P5 tests, full `pytest tests/python -q`,
CMake/CTest, `git diff --check`, protected-path diff checks, schema/JSON/hash
recomputation, duplicate/cross-case/stale/split/lineage/no-overwrite and
manifest completeness audits. Confirm no hardware command was run. Report
non-hardware completion, hardware status, remaining minimal gaps, and whether
the P8 completion gate and next-phase entry are satisfied.
