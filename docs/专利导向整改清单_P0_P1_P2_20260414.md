# 专利导向整改清单 `P0/P1/P2`（2026-04-14）

## 1. 目的

本清单基于以下评审结论收敛：

1. `realization` 已具备可运行的 evidence export 主路径，但与专利导向详细设计相比，仍存在“确定性、控制面工作集、Mode-B 独立性、导出前校验、1GB 证明性验证、合同冻结”六类关键缺口。
2. 当前问题不是“从零实现”，而是把已有最小闭环推进到“可作为专利主实施例和工程主路径交付”的状态。
3. 整改必须避免再次把主路径拉回 legacy `clipped/source-backed` 语义。

本清单只覆盖：

1. `P0` 必修项：不修会直接削弱专利主张或导致主路径口径不稳。
2. `P1` 主实施例收口项：把当前实现从“可运行”推进到“standalone two-pass 主路径成立”。
3. `P2` 证明性和收口项：围绕 `1GB`、合同冻结和下游消费补齐专利证明力。

---

## 2. 总体修改顺序

推荐总顺序固定如下，避免返工：

1. 先做 `P0-1 ~ P0-3`
2. 再做 `P0-4 ~ P0-5`
3. 然后做 `P1-1 ~ P1-4`
4. 再做 `P1-5 ~ P1-7`
5. 最后做 `P2-1 ~ P2-5`

约束：

1. 没完成 `P0-1` 前，不要扩展 `proof_digest` 字段。
2. 没完成 `P0-2` 前，不要宣称 package sidecar 是 evidence job workset。
3. 没完成 `P1-2` 前，不要把 `Mode-B` 作为正式主实施例对外宣讲。
4. 没完成 `P2-2` 前，不要把当前 evidence proof archive 当作 `1GB` 级最终证明材料。

## 3. `P0` 必修项

### `P0-1` 固定 `snapshot_id / proof_hash` 的确定性语义

目标：

1. 让同一输入、同一 budget、同一 sidecar 下的 `proof_hash` 可重复。
2. 解除当前 `snapshot_id` 使用时间戳导致的非确定性。

涉及文件：

1. `realization/parser/evidence_models.py`
2. `realization/desktop/evidence_export.py`
3. `realization/tests/python/test_evidence_models.py`
4. `realization/tests/python/test_desktop.py`
5. `realization/tests/python/test_repro_evidence.py`

修改项：

1. 明确 `snapshot_id` 的语义边界：
   - `Mode-A` 采用基于冻结输入的稳定派生值，而不是当前时间戳。
   - `Mode-B` 继续绑定外部 sidecar manifest 的 `snapshot_id`。
2. 保持 `proof_hash` 仅覆盖详细设计冻结字段，不把路径、当前时间、输出目录等运行时噪声混入。
3. 补单测证明：
   - 同一输入重复导出两次，`proof_digest.proof_hash` 一致。
   - 改变 `budget_vector` 或 `rule_family` 时，`proof_hash` 发生变化。

验收标准：

1. `Mode-A` 连续两次 evidence 导出 `proof_hash` 相同。
2. `repro_OpenPackage()` 对旧包和新包仍兼容。

顺序：

1. 先改 `evidence_models.py`
2. 再改 `evidence_export.py`
3. 最后补测试

### `P0-2` 把 package sidecar 从“全量构建结果”收敛为“本次 evidence job 工作集”

目标：

1. 对齐详细设计“package 中默认写当前 evidence job 的控制面工作集”要求。
2. 让 `dependency_sidecar.jsonl` 真正表达本次导出的闭包控制面，而不是数据集级全量边集。

涉及文件：

1. `realization/desktop/evidence_export.py`
2. `realization/parser/evidence_closure.py`
3. `realization/parser/evidence_sidecar.py`
4. `realization/desktop/package_writer.py`
5. `realization/tests/python/test_desktop.py`
6. `realization/tests/python/test_evidence_contract_assets_simtool.py`

修改项：

1. 在闭包执行过程中显式保留“本次用到的边集合”：
   - seed 关联边
   - round projection 进入候选集合的边
   - bounded/degraded 时被冻结 frontier 对应边
2. 写包时不再直接落整个 `sidecar_seed_rows`，而是只写 workset sidecar。
3. 若 `Mode-B` 输入为外部 sidecar，包内 sidecar 仍只写 job workset，但 manifest/source 校验继续绑定原始外部 sidecar。
4. 补回归测试证明：
   - 包内 sidecar 小于或等于输入 sidecar
   - 包内 sidecar 覆盖 proof bundle 与 frontier 所需工作集

验收标准：

1. `control/dependency_sidecar.jsonl` 不再是 bundle 全量边集。
2. `bounded/degraded` 包的 sidecar 仍足够支撑 repro proof 校验。

顺序：

1. 先在 `evidence_closure.py` 补状态留痕
2. 再在 `evidence_export.py` 裁切 workset
3. 最后在 `package_writer.py` 和测试里收口
